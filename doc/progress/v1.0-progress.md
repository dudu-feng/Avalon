## 二、架构决策记录

### 决策 1：agent/ 层零修改策略

**背景**：最初计划在 `agent/loop/react_loop.py` 增加 `on_event` 回调参数，在 `session_manage.py` 给所有函数增加 `session_id` 参数。

**决策**：用户要求将所有改动从 `agent/` 移出，在 `server/services/` 中独立实现，保持 agent 层纯净。

**实现方式**：
- `chat_service.py`：自包含 `streaming_react_loop()` 函数（~230 行），完全复制原始 ReAct 循环的核心逻辑，在每个关键节点通过 `on_event` 回调推送进度事件。
- `session_service.py`：自包含多会话管理逻辑（~270 行），直接操作文件 I/O（JSON 读写、目录遍历、shutil 删除），仅在需要压缩/持久化时委托给 `session_manage.session_compress()` 和 `session_manage.save_current_session()`。
- agent 层文件 `react_loop.py`（149 行）和 `session_manage.py`（350 行）保持原始版本不变。

**代价**：`chat_service.py` 中有与 `react_loop.py` 高度重复的 ReAct 循环代码。如果 agent 层的循环逻辑发生变化，需要同步更新 service 层。

### 决策 2：Sync-to-Async 桥接方案

**问题**：LangChain `ChatOpenAI.invoke()` 是同步阻塞调用，FastAPI 需要异步以避免阻塞事件循环。

**方案**：
```
HTTP 请求 → FastAPI async endpoint
                │
                ├─→ asyncio.Queue() 创建事件队列
                ├─→ loop.run_in_executor() 在线程池运行同步 ReAct
                │       │
                │       └─→ on_event 回调 → call_soon_threadsafe → queue.put()
                │
                └─→ async generator 从 queue 读取 → StreamingResponse (SSE)
```

`call_soon_threadsafe` 确保了跨线程安全——同步回调在 worker 线程中执行，通过它将事件安全地推入事件循环拥有的 `asyncio.Queue`。

### 决策 3：单一活跃会话约束

**背景**：原始 `session_manage.py` 只管理一个 `terminal.json` 文件。多会话是通过"归档-新建"模式实现的。

**决策**：保持这个约束——同一时间只允许一个活跃会话。历史会话可以在任意时间浏览和删除。

**实现**：`session_service.py` 不修改 agent 层，而是：
- `create_session()` → 先归档当前会话→写入新的 `terminal.json`
- `list_sessions()` → 读 `current/terminal.json` + 遍历 `history/terminal/*/`
- `delete_session()` → 只能删除 history 下的会话，活跃会话拒绝删除（40002）

## 五、遇到的错误和修复

### 1. TypeError: `T | None` 语法不支持

- **原因**: `schemas/common.py` 使用了 `data: T | None`，但最初假设的 Python 3.9 不支持此语法
- **修复**: 改为 `Optional[T]`
- **实际**: AI 环境是 Python 3.11，两种语法均可用

### 2. ModuleNotFoundError: `loop` 导入失败

- **原因**: `server/` 和 `agent/` 是兄弟目录，`agent/` 不在 Python 搜索路径中
- **修复**: 在 `server/main.py` 开头添加 `sys.path.insert(0, _agent_dir)`

### 3. ZVec 数据库锁

- **症状**: `RuntimeError: Can't lock read-write collection`
- **原因**: 
  - ZVec 内部使用 RocksDB，异常退出后 LOCK 文件残留
  - 多个进程同时访问会冲突
  - 冷启动 ZVec 打开数据库需要 ~15 秒
- **修复**: 
  - 删除残留的 LOCK 文件（`zvec/LOCK`, `idmap.0/LOCK`, `fts.1.rocksdb/LOCK`）
  - 确保一次只有一个进程访问

### 4. Config PUT 50007 错误

- **原因**: `config_service.py` 中 `_find_env_path()` 使用 `os.path.abspath(env_config.__class__.__module__)`，但 `__module__` 返回的是模块名字符串 `"config.env_config"`，不是文件路径。拼接后的路径指向了项目根目录而不是 `agent/.env`。
- **修复**: 改用 `inspect.getfile(env_config.__class__)` 获取真实文件路径

### 5. curl 中文 JSON 解析失败

- **症状**: `POST /api/v1/memory/search` 返回 "There was an error parsing the body"
- **原因**: Git Bash 环境下，curl 传递中文 JSON 字符串存在编码问题
- **确认**: 用 Python 端验证 Pydantic Schema 解析中文完全正常；用 ASCII 内容的 curl 请求也正常返回。这是终端工具问题，不影响实际 API 功能。

## 六、关键代码片段

### 自包含流式 ReAct 循环

`server/services/chat_service.py` (~230 行) 的核心结构：

```python
def streaming_react_loop(user_input, on_event=None):
    chat_history = []
    chat_history.append({"role": "user", "time": get_current_time(), "content": user_input})
    _emit("chat_start", {"message_id": message_id}, on_event)

    while True:                              # 对话层循环
        chat_result = llm.llm_chat(...)
        chat_result_content = parse_llm_json(chat_result.content)
        _emit("chat_thought", ...)
        _emit("chat_message", ...)
        chat_history.append(...)

        if next == "stop": break
        if next == "action":
            _emit("action_start", ...)
            while True:                      # 动作层循环
                action_result = llm.llm_action(...)
                _emit("action_step", ...)

                if next == "finished": _emit("action_finished", ...); break
                elif next == "tool_call": 
                    _emit("action_tool_call", ...)
                    tool_result = _execute_tool(...)
                    _emit("action_tool_result", ...)
                elif next == "sub_analysis":
                    _emit("action_sub_analysis", ...)

    _emit("done", {"chat_history": chat_history}, on_event)
    return chat_history
```

### SSE 桥接

```python
async def generate_sse(session_id, message):
    queue = asyncio.Queue()
    event_loop = asyncio.get_event_loop()

    def on_event(event_type, data):
        event_loop.call_soon_threadsafe(queue.put_nowait, (event_type, data))

    def run_react():
        history = streaming_react_loop(message, on_event=on_event)
        session_manage.update_current_session(history)
        session_manage.auto_compress_check_from_history(history)

    asyncio.get_event_loop().run_in_executor(None, run_react)

    while True:
        event_type, data = await queue.get()
        yield format_sse(event_id, event_type, data)
        if event_type in ("done", "error"):
            break
```
